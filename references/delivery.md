# 交付物格式与证据规范

## 0. 状态词表（唯一权威，固定取值，不新造同义词）

| 工件 / 字段 | 固定取值 | 说明 |
|---|---|---|
| subdomains.csv · 状态 | 存活 / 不存活 / NXDOMAIN / 未探测 | NXDOMAIN 条目保留（接管排查对象） |
| 入口清单.csv · 条目状态 | 未验证 / 待批准 / 已验证 / 未确认 | 未确认 = 网络层失败；待批准 = 响应体挖掘产物，须用户点名后方可验证 |
| 入口清单.csv · 验证结果 | 未鉴权可读 / 需凭据 / 不在此前缀 | 仅「已验证」条目填写；「未确认」条目留空。细节差异（业务层校验、方法不符、响应摘要）写备注列 |
| 下载日志 · 判定 | OK / TRUNCATED / CL_MISSING / CHUNKED / FAILED / HTTP_&lt;状态码&gt;（脚本输出实际码：3xx / 4xx / 5xx，如 HTTP_403） | safe_fetch 输出。TRUNCATED / CL_MISSING = 数据不完整，不得用于提取。CHUNKED = chunked 传输无 CL 的**传输形态，非缺陷**：200 且非空 ⇒ **可用于提取**，产物标注"不可校验"，单独计数不进重试。HTTP_&lt;4xx&gt; = 响应完整但非成功：错误体/路径回显按存在性证据记入清单并标"来自错误响应"，WAF 拦截页与默认页只记"存在被拦"信号（确定性结果，不重试）。HTTP_&lt;3xx&gt; = 重定向异常（跟随死循环/未跟随成功），记录复查。HTTP_&lt;5xx&gt; = 多为瞬态，重试耗尽按未确认处理 |

## 1. 入口清单 `入口清单.csv`（核心产物=待办清单；报告位置 = §3 接口清单）

| 列 | 说明 |
|---|---|
| URL | 完整可访问形态（基址+路径，动态段保留 `{param}` 占位符） |
| 方法 | 已知方法；未知标 `?` |
| 参数 | 已知参数名（来源见 phase2 §3「参数名来源」：脚本 参数名/query 列、归档 URL 查询串），未知留空 |
| 来源 | 页面引用 / JS提取 / 运行时捕获 / 响应体提取 / 历史归档 / 移动端提取 / PROBE(自己构造的探测) |
| 站点 | 归属站点（见 §1.5 定义；URL 的 host ≠ 归属——www 站引用 api 子域接口时归属仍是 www） |
| 状态 | 条目状态，取值见 §0 状态词表 |
| 验证结果 | 验证结果，取值见 §0 状态词表 |
| 备注 | 业务归属、鉴权线索、后续测试方向 |

规则：
- 每条必须能回答来源；自己构造的探测标 PROBE，**不与真实端点混排**。
- 提取器形态 → 来源列映射（写死，不靠语义对号）：`html` 形态 → 页面引用；`url / hidden / concat / json / css / fetch / ws / sse / wss-url / graphql-op / absolute` 形态 → JS提取（方法列自带 WSS/SSE 标记，absolute 自带域外标注）；apk/ipa 静态提取 → 移动端提取；**备注列保留具体形态字样**（json/html/css/concat）。
- **多站点分次产物的合并规则**（每站一个 extract CSV 并入入口清单时）：去重键 = (URL, 方法)。同键跨站并为一行：站点取首个发现站，备注记"亦见于 &lt;他站&gt;"；状态取信息更全者（已验证 &gt; 未验证 &gt; 未确认）；两条已验证结果冲突 → 状态改已验证、验证结果记首个、备注标"跨站结果不一致，疑构建漂移"（本身是有价值的发现）。
- 未验证条目是**待办**：滚动补测或明确标注跳过原因（需凭据/属写操作/超范围）。
- 报告里的计数必须是工具输出，禁止人脑估数。
- 置信度由来源列推导，不另设词表：两源重合（静态+运行时）> 单源 > 归档/推断。归档与单引擎独有条目在备注标"待复核"。

## 1.5 其余产物 schema（下游自动消费的列契约；报告位置列 = 该文件的内容落在报告哪一节）

| 产物 | 报告位置 | 列（依次） | 备注 |
|---|---|---|---|
| `fingerprints.csv` 指纹表 | §2 资产与指纹 | 组件, 版本串, 判定来源, 证据, 站点 | 判定来源 = 规则库 / 响应头 / Cookie / 错误页 / 规则正则；证据 = 命中的响应文件与头（用规则库时含库名与 commit）；版本以响应原文为准 |
| `leaks.csv` 泄露点清单 | §4 信息泄露点 | 级别, 类别, 内容, 上下文, 来源文件, 站点 | 级别 = 高 / 中 / 低；内容打码按长度分级：≥10 保留前 4 后 4，6–9 保留前 2 后 2，<6 全遮（短串前4后4等于全露）；类别 = AK/SK、JWT、内网 IP、签名逻辑、SaaS app_id（**公开标识类只入低级别**，备注标公开标识——定级权威见 phase2 §6）、DB 连接串、wss 端点等 |
| `clues.csv` 注释线索清单 | 核验后并入 §4（线索期不在报告） | 类别, 内容, 置信, 上下文, 来源, 重复次数, 站点 | 与 `scan_comments.py` 的 CSV 输出列**逐字一致**（脚本为权威出处，`--site` 传入）；核验后才升级进泄露点清单 |
| 高危发现 | §1 结论摘要 | 非独立产物 | 见下 |

**站点列定义（入口清单 / fingerprints / leaks / clues 四产物共用）**：值 = `subdomains.csv` 中状态=存活的**子域名**——即阶段 2 的覆盖单位，与报告"站点覆盖 M/N"同单位；非标端口站点记 `host:port`。与入口清单"基址"的区别：基址是接口的 API 前缀根（一个站点可挂多个基址，一个基址也可服务多个站点），站点是**资产归属单位**。多站点测绘时来源文件名会撞名（两个站点都有 app.js），站点列是唯一归属维度——**为空即交付缺陷**。

**归属在生成时打标，不事后补填**：脚本产物经 `--site` 透传（extract_endpoints / scan_comments，多站点按站点目录分次运行各传各的）；手工产物（fingerprints / leaks）在处理该站点的当口登记——多站点几百行靠记忆回补必错，这正是来源文件撞名同一类事故。

**移动端条目的站点取值（三态）**：站点直链下载的 apk → 该站点；应用商店元信息 → 主域（备注标"商店来源"）；用户提供的包 → `-`，且备注必须写明提供者——无归属要显式，不留空给下游猜。

**高危发现的双向定义（当且仅当，不是任一侧）**：`leaks.csv` 级别=高 ⇔ 报告 §1 有对应条目。级别=高 是**证据行**，§1 条目是**上报落点**（发现即报，不等报告写完）——只在 leaks 不在 §1 = 没报；只在 §1 不在 leaks = 报了没证据。收尾自检：**leaks 高行数 == §1 高危条目数**，不等即为交付缺陷。仍不另设第三份文件。

下游做 指纹→CVE 比对、泄露→定级 时按本表列名消费，不猜。

## 2. 测绘报告 `测绘报告.md`

固定结构：

```
# <目标> 测绘报告
## 0. 授权边界声明   （范围 / 未触及 / 操作性质 / 是否触发拦截 / 留痕位置，表格）
## 1. 结论摘要       （编号列表，每条一句话+指向证据，可附后续方向一句话；高危发现在此出现）
## 2. 资产与指纹     （子域名清单摘要 + 组件指纹表 + 站点覆盖 M/N 及未覆盖原因）
## 3. 接口清单       （按业务模块分组；两个率分开标——
                      接口实测率 = 阶段3已验证 / 阶段2提取（限已覆盖站点）；
                      站点覆盖率 = 阶段2已覆盖 / 存活站点数，见 §2）
## 4. 信息泄露点     （每条附上下文证据；高危标注级别）
## 5. 未闭环清单     （未验证入口 / 跳过项及原因 / 存疑结论 / 信息缺口：子域来源是否单一、端口覆盖度、未覆盖站点）
```

## 3. 证据规范

- **每条结论指到一次真实请求**（抓包工具里的 flow/请求编号，或落盘的编号响应文件）。指不到的标「推断，未验证」。
- 关键发现的落盘三件套：`<编号>.body` + `<编号>.headers` + `<编号>.sha256`（校验和 sidecar，防篡改质疑）。
- 关键发现给出**最小复现**：一条可重放的请求描述（方法+URL+关键头），他人按此能复核。
- 响应字节数与复测一致 ⇒ 写明"稳定复现"；不一致 ⇒ 标"偶发，待复查"。
- 阴性结论也是产出：某类泄露"0 命中"、某探测"未触发拦截"都如实记录，防止后续重复劳动。
- 报告中出现的凭据/密钥样例打码（保留前 4 后 4 位与类型），全文可 grep 复核无完整凭据。
- 高危发现（未鉴权敏感数据、密钥泄露）**发现即报**，不等报告写完。

## 4. 诚实性条款

- 修正过程写进报告（哪条结论改过、依据是什么）——这是可信度的来源。
- 三分类并列呈现：**已证实 / 已否定 / 跳过**。只报已证实会让人以为其余没问题。
- 启发式产物（推断的用途、导出名含义）标注"已提取 ≠ 已校验"。

## 5. 下游交接协议（每条"不做"必须有交接物与接收方）

边界产物不是废料，是下一阶段的输入。交接以**表为权威**（行数随边界类别增长，散文不计数）；其中「可未授权写入」定级行是写入测试的定级出口，不构成独立边界：

| 边界（本技能不做） | 交接物 | 接收方与前置条件 |
|---|---|---|
| 接管验证（不注册资源验证占用） | `subdomains.csv` 接管嫌疑行（子域 + CNAME + 指纹） | 后续独立任务；需授权覆盖对应云平台的资源操作 |
| 密钥 live/dead 验证（不调第三方 API） | `leaks.csv`"疑似真实密钥"条目（内容打码，原件在证据文件） | 用户批准后的独立验证任务；只读验证器 |
| 写入 / 越权 / 注入测试 | `入口清单.csv` 标"鉴权拦截未覆盖"或高价值类别的条目 + 阶段 3 响应摘要 | 漏洞挖掘阶段；须用户逐次批准 |
| SaaS 悬挂验证（TXT token / MX 推断出的平台） | 报告 §2 的组织级 SaaS 资产行（平台 + token + 域） | 授权后的悬挂验证任务——凭 token 证明所有权 ≠ 抢注，是"不注册资源"红线的正当例外，但属 SaaS 平台操作须授权 |
| 「可未授权写入」定级 | 与「写入 / 越权 / 注入测试」行相同：入口清单"鉴权拦截未覆盖"或高价值条目 + 阶段 3 响应摘要（含备注） | 漏洞挖掘阶段；须用户逐次批准；该结论必须真发写方法才成立，本技能永不产出 |

交接规则：

1. **未闭环清单即交接清单**——收尾时它是"剩余攻击面"的唯一权威视图，下游从这里取活。
2. 交接只传文件与行级指针（来源列 / 证据列 / 备注），不传结论——下游自己验证、自己定级。
3. 前置条件未满足（授权 / 批准）时，交接物原地保留并计入未闭环清单，不算丢失。
4. 本技能对交接物的责任到"证据可复核"为止（证据规范 §3），下游验证失败不回溯修改测绘结论，只在未闭环清单标注。
