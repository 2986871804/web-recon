# 排错：环境问题 ≠ 目标问题

十一种常见假象，每一种都先怀疑自己的链路。方法：**对照组**——同环境访问一个已知正常的外部站，对照结果定位责任方。对照组请求也是证据，保留。

| # | 假象 | 看起来像 | 排查顺序 |
|---|---|---|---|
| 1 | TLS 握手失败 / 连接重置 | 站点挂了 | ① 对照组正常 ⇒ 目标侧拦截（WAF 掐 TLS 常见）② 对照组也失败 ⇒ 本机/代理问题 ③ 走代理时自签 CA 需忽略证书校验（curl `-k`） |
| 2 | 一批请求集体超时 / 502 | 服务器坏了 | 突发速率触发限速。停手等窗口（同批隔天常全部正常）。代理 Warning 头可区分代理侧超时 vs 目标侧断连 |
| 3 | 全部 404 | 接口不存在 | ① 挂别的前缀（对 `/api/` 发 1 发）② 反代剥离前缀 ③ 无 SPA 回退。404 按体积/类型二分（见 phase3-api-verification.md 判定表） |
| 4 | 下载"成功"但解析异常 | 有隐藏模块 | 文件被静默截断，校验 Content-Length（phase2-fingerprint-js.md §2） |
| 5 | 200 但 body 是错误信息 | 接口坏了 | 业务码与 HTTP 码脱钩，打开 body 看业务码（phase3 判定表） |
| 6 | 数据混入陌生域名流量 | 目标有这些资产 | 抓包库 / 浏览器后台流量（更新服务、遥测）混入。先按 host 分组过滤；自己的探测标 PROBE，与真实发现分开 |
| 7 | 结论"只有 N 个接口" | 采样当穷举 | 并列实测率（实测 N / 总数）；启发式字段标"已提取 ≠ 已校验" |
| 8 | 重定向后内容变了 | 命中了泄露 | 探测请求**禁用跟随重定向**（curl 不加 `-L`）；原响应与重定向目标分别归类后再判定。safe_fetch 属下载场景，跟随重定向合理（判定作用于最终响应），不在禁例 |
| 9 | 归档里的端点直接入清单 | 历史资产 | Wayback 端点可能已死/已易主，复验存活后才进清单 |
| 10 | 响应内容直接管道进脚本处理 | 命令注入自己 | 不可信响应先落盘、检查，再处理本地文件 |
| 11 | 外部情报里的诱捕主机 | 真实资产 | 高价值暴露（数据库裸奔类）先查蜜罐概率（如 Shodan honeyscore）再排优先级 |

## 请求模板（跨平台 curl）

```bash
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36"
# 走代理（Burp / Yakit / mitmproxy 任一）：
curl -k -s --proxy http://127.0.0.1:8080 -A "$UA" -m 20 -D resp.hdr -o resp.body \
     -w "%{http_code}|%{size_download}" "https://<目标>/"
# 无代理：去掉 --proxy 和 -k
```

- `-k`：代理自签 CA 时必须；无代理直连可去掉。
- `-A`：始终带浏览器 UA——部分 WAF 直接拦非浏览器 UA。
- 超时给足（走代理时单次 1-8 秒波动都正常），外层写 3-5 次重试循环，`000` / `502` 都算失败。
- `-w` 输出状态码与字节数，与落盘文件比对。

## 代理与留痕（可选但推荐）

- 有抓包代理时，所有请求走代理：留痕 + 事后复盘。
- 无代理也能跑通全流程，靠脚本落盘留痕（响应头 + 正文编号保存）。

## Windows 注意（在 Windows 上执行时）

| 现象 | 解法 |
|---|---|
| PowerShell 回显被吞 | 结果 `Out-File -Encoding utf8` 落盘后读文件 |
| 长循环 exit 1 且无输出 | 超时被杀：显式传 timeout，每轮迭代落盘（增量结果不丢） |
| 子进程中文输出乱码 | 管道按 GBK 解码：脚本用自带 `--out` 落盘，不接管道 |
| `Invoke-WebRequest` 自签证书报错 / 大文件写空 | 用 curl.exe |

## 脚本环境

- Python 3.8+，仅标准库。
- `hook_inject.js` 无依赖（控制台粘贴或 evaluate 注入）。
- `yakit_db_probe.py` 仅 Yakit 用户有意义。

统一落盘参数（五个 Python 脚本一致，均 UTF-8，Windows 下避免管道 GBK 乱码；**`--log` 不要落在 `--out` 下载目录内**——下一轮提取会把它当文本文件扫入）：

| 脚本 | `--out` | `--log` |
|---|---|---|
| safe_fetch.py | 下载目录 | 控制台输出改写文件（不打印） |
| extract_apis.py | 报告文件（仍打印） | 控制台输出改写文件（不打印） |
| extract_endpoints.py | 报告文件（仍打印）；另有 `--csv` 数据、`--site` 归属打标 | 控制台输出改写文件（不打印） |
| scan_comments.py | 报告文件（仍打印）；另有 `--csv` 数据、`--site` 归属打标 | 控制台输出改写文件（不打印） |
| yakit_db_probe.py | 报告文件（重定向） | 同 `--out`（本脚本结果即控制台输出） |

脚本自检（离线，零目标请求）：

```bash
python evals/run_regression.py        # 分组覆盖面见该脚本文件头；断言数以运行输出为准（数字不复制，防漂移）
```

**改动任一脚本后先跑它。** 判定联动这类机制不会崩，只会**静默失效**——报告里照样写着"排除 N 个"，实际一个没排。这类退化只有断言能拦住，肉眼 review 拦不住。
