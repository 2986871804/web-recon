# 阶段 3：API 验证

## 定位

回答两个问题：接口存在吗？鉴权拦到它了吗？越权、写入、注入验证不做（硬性规则 1 + 先地图后判断）。

## 选候选

优先验证最可能免鉴权的 5-10 个：

- 路径含 `public / anonymous / noLogin / open / guest / free`（作者命名即线索）
- 语言包产出的词（passwordlessLogin / export / permission 这类 i18n 高频接口名——见 phase2 §2 二跳补抓）
- **响应体挖掘回流的新条目**（来源=响应体提取，见下节）
- 页面启动时调用的（站点信息 / 菜单 / 主题 / 按域名查询）
- 空参数可响应的列表类

未选的留待办（硬性规则 3）。候选排序信号：响应带调试头（X-Debug/堆栈）> 报错信息冗长 > 401/403 资产（后续测绕过的高价值面）> 响应体小（薄应用，防护弱）> 非主流 Server 头（冷门栈，可能未打补丁）。

## 响应体挖掘（递归发现）

```bash
python scripts/mine_responses.py --dir <body目录> --entry-list 入口清单.csv --csv mined.csv
```

每条已验证接口的响应正文本身是接口发现数据源。验证一个接口后，打开响应体 grep 以下形态，命中的新路径回流入口清单（来源=响应体提取，状态=未验证），新条目回到验证循环继续——**递归直到预算用完或无新发现**。

**挖掘模式**（对已落盘的 .body 文件执行，零额外请求）：

| 模式 | 形态 | 暴露什么 |
|---|---|---|
| 路径值 | `"/api/..."`, `"/v[0-9]/..."`, `"/[a-z]+/[a-z]+"` 在 JSON 值中 | 代码里没写死、由服务端下发的动态接口 |
| HATEOAS 链接 | `"links": {"next": "...", "related": "..."}` | REST 资源图的全貌 |
| 错误回显 | Spring Boot `"path": "/api/v2/..."` | 版本漂移——v2 存在但你只测了 v1 |
| URL 值字段 | `"upload_url": "/api/upload"`, `"callback": "/api/cb"` | 功能性端点 |
| 嵌套资源 URI | `"/api/users/123/orders"` 在数据字段中 | 你不知道的子资源 |

**去重**：新发现的路径须先与入口清单已有条目比对（含占位符归一化——`/users/123/orders` 与 `/users/{id}/orders` 同键），已有条目不重复入清单。

**预算控制（防递归爆炸）**：
- 响应体挖掘本身**零请求成本**（纯本地 grep）
- 但新条目的**验证**消耗阶段 3 预算（≤50 发/会话）
- 预算用完时，未验证的响应体挖掘条目全部转待办（下会话继续递归）
- 单轮递归深度建议 ≤3 层（A 的响应发现 B，B 的响应发现 C，C 的响应发现 D——到 D 通常已无新发现，深度超过 3 大概率在兜圈子）

## 速率参数（数值的唯一出处 = SKILL.md 阶段 3 规则，此处不复制防漂移；下列为该规则未覆盖的执行细节）

- 网络层失败（超时、代理错误、连接重置）可重试、业务响应（含 4xx/5xx）不重试——次数上限的唯一出处 = SKILL.md 阶段 3 规则。
- 成簇 403 / 超时：停。补 1 条已知正常请求判断"瞬时限速 vs 持久封禁"；瞬时等窗口，持久记录后换目标。不尝试绕过。
- 每条请求的响应头 + 正文落盘（编号对应清单行）——结论的唯一依据。

## 判定表

很多接口用 HTTP 200 包裹业务错误（`{"code":-1,"message":"需要登录"}`）。**必须打开响应体看业务码**。结论取值以 delivery.md §0 词表为准：

| 响应形态 | 验证结果 | 备注 |
|---|---|---|
| 200 + 业务成功码 + 数据 | 未鉴权可读 | 单条无凭据请求即是证据 |
| 200 + 业务错误码 | 需凭据 | HTTP 层未被拦、业务层校验——**读 message 区分鉴权类与参数类错误**（参数缺失也落此格，备注写清）；应返回 401 却返回 200 可记为设计问题 |
| 401 / 403 + 鉴权提示 | 需凭据 | 基线，正常态 |
| 404 + 框架错误体（小体积 JSON、回显 path） | 不在此前缀 | ≠接口不存在，换前缀可再试一次 |
| 404 + 大体积 HTML（Web 服务器默认页） | 不在此前缀 | 命中静态服务器，无额外信息 |
| 405 + `Allow:` 头 | 在 GET/HEAD/OPTIONS 与 Allow 的交集内换方法重试后再判；交集为空则记录后跳过 | 存在但方法不符 |

**网络层失败（超时、代理错误）不是判定结论**：条目状态改「未确认」、验证结果留空；不得写成「不在此前缀」，也不得写成不存在。

国际/REST 规范风格的示例（与上表同构落位，补齐示例生态）：`401 + {"error":"unauthorized"}`（OAuth2 风格）→ 需凭据；`404 + {"message":"Not Found"}`（Express/REST 风格小体积 JSON）→ 不在此前缀；`403 + {"detail":"..."}`（DRF 风格）→ 需凭据。用 HTTP 状态码规范返回的 API 与业务码包络型（200+code）API 都在表内，判定规则本体一致。

## 低成本高信息的一发流（按需选用）

- **前缀探测**：对 `/api/` 发 1 发。返回框架原生 404 且回显 `path` ⇒ 反代剥离了前缀，相对路径接口都能经本站访问，不用碰域外地址。
- **HEAD 判资源直链**：接口吐出文件直链时，1 条 HEAD 看 Content-Type / Content-Length / Accept-Ranges 即定论，不下载内容。
- **分页上限递增**（size=1/10/100/500）：实际返回数跟随请求 ⇒ 服务端无截断——量化"数据可批量拉取"程度的证据。
- **参数对照**：同一参数传"合理值"与"明显不存在的值"，响应逐字节一致 ⇒ 参数不影响取值（≠可枚举，不过度定级）；不一致 ⇒ 记录差异。
- **鉴权拦截判定**：对清单接口发 1 条无凭据 GET，落在 401（拦截器先生效）还是 200+方法不支持异常（请求已抵达业务层）——后者说明鉴权拦截器未覆盖该路径。结论只写到「鉴权拦截未覆盖」。
- **500 判读**：500 = 请求已抵达后端并触发异常，保留请求样本并在备注标注（后续注入/逻辑测试候选，本阶段不测）。
- **CORS 带实测**：对关键端点带 `Origin:` 头发 1 发，只记录是否反射与 credentials 标志；根路径无 CORS 头 ≠ 全站无（逐端点判定才有效）。

## 红线（硬性规则 1 的阶段展开）

- 写方法（POST / PUT / DELETE / PATCH）一律不发——包括空 body 探测写接口是否免鉴权。确需测试写入，属后续独立任务，须用户逐次批准。
- 不上传文件、不提交表单、不触发验证码。
- 响应出现个人敏感信息（证件、手机号明文）：取证已达目的，停止扩大取样，立即报告。
- 结论措辞上限：「鉴权拦截未覆盖」「数据未鉴权可读」；「可未授权写入/修改」需要写方法验证，不在本阶段。

## 产出

更新入口清单（权威词表见 delivery.md §0）：已验证条目状态改「已验证」、验证结果填三值之一，备注写响应摘要（状态码/业务码/字节数）；网络层失败条目状态改「未确认」、验证结果留空，留待办。字节数与复测一致 ⇒ 稳定复现而非偶发，写进备注。
